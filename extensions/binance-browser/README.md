# 千羽 Superbot · 币安聊天桥接

版本：0.1.11（实验版）。需要 Google Chrome 116 或更新版本，以及包含币安桥接功能的 Superbot 后台。

v0.1.11 补齐异常退出后的临时权限回收、权限回收期间的操作锁，以及授权响应丢失时的“结果未确认”提示。插件后台重启时先撤回上次未清理的 Cookie 权限，再接受新的主动授权；不会自动读取 Cookie 或重新提交。

本版增加一键授权服务器直连：仅在用户明确勾选并点击后申请临时 Cookie 读取权限。浏览器桥接和图文群发保持兼容。图片经官方群预上传和签名 PUT 上传，再匹配本群、本账号、图片对象键及说明的真实消息回执，不额外发送第二次图片。不确定结果不会自动重发。

升级时覆盖原扩展目录，在 `chrome://extensions` 点击扩展卡片的重新加载，再刷新币安聊天页。保留原目录路径可继续使用已保存的配对配置，不需要重新配对；不要同时启用新旧两份桥接。

## 在服务器安装

1. 将 ZIP 上传到服务器并解压，保留整个 `binance-browser` 文件夹。不要只复制某个 JS 文件，也不要直接把 ZIP 拖进 Chrome。
2. 在服务器的 Google Chrome 中打开 `chrome://extensions`，开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择解压后的 `binance-browser` 文件夹。所选文件夹里应能直接看到 `manifest.json`。
4. 在同一个 Chrome 配置中打开币安聊天页，正常完成登录。支持 `https://www.binance.com/zh-CN/square/chat`，也支持旧入口 `https://www.binance.com/zh-CN/chatroom?channelId=GROUP_ID`。已经打开的聊天页请刷新一次。
5. 在 Superbot 后台的“连接账号”创建“币安聊天 · 浏览器会话桥接（实验）”，填写连接名称。
6. 复制后台生成的配对 JSON，点击 Chrome 工具栏中的桥接扩展，将 JSON 粘贴到“配对配置”，点击“保存并连接”。
7. 扩展显示“已连接”后，在后台“连接账号 → 管理同步群”自动读取已加入的聊天室，勾选后保存。后续可以随时增删，原配对继续使用。保持 Chrome、该配置和币安聊天标签打开。

后台和 Chrome 在同一台服务器时，桥接可以连接 `ws://127.0.0.1:3000/api/v1/connectors/binance/socket`。后台在其他机器上时，需要可访问的 WSS 地址，例如 `wss://bot.example.com/api/v1/connectors/binance/socket`。

**`127.0.0.1` 指运行 Chrome 的那台机器。** 扩展安装到服务器后，不能通过这个地址连接开发电脑上的后台。应在实际后台设置正确的 `PUBLIC_ORIGIN`，并从该后台重新生成配对配置；远程反向代理需支持 WebSocket Upgrade。

配对密钥不随安装包提供。它由你的后台生成，保存在本机扩展存储中；不要公开分享。配对配置丢失时，在后台点击“重新配对”，旧配置立即失效。浏览器桥接不需要提交币安 Cookie；可选的服务器直连需要你明确授权指定登录凭据。两种方式都不需要账户密码或交易 API Key。

## 一键授权直连

1. 更新时覆盖**原扩展目录**，在 `chrome://extensions` 点击“重新加载”，然后刷新币安聊天页。目录路径不变即可保留原配对，勿同时启用多份。
2. 在同一 Chrome 配置中登录币安聊天页，打开插件，核对“一键授权服务器直连”下显示的后台域名与连接账号。
3. 勾选授权，点击“读取并授权直连”，按 Chrome 提示允许本次 Cookie 读取。无需进入开发者工具或手动复制值。
4. 插件先与后台用原配对密钥双向验证，再从聊天标签对应的 Cookie 存储中读取 `p20t`、`cr00` 和可选的 `BNC_FV_KEY`，通过 WSS 发给你已配对的后台。其他 Cookie、密码、交易 API Key 不会读取。
5. 后台验证账号、已选群、消息读取和聊天心跳后才加密保存并切换。此步骤不发送任何群消息。显示成功后可关闭网页、Chrome 或扩展；群选择与历史消息保持原样。
6. 验证失败保留原连接；提交后断线会显示“结果未确认”，需查看后台，插件不会自动重试。
7. 临时 `cookies` 权限在此次操作结束后撤回；插件不保存导出的登录字段，也不监听 Cookie 变化或自动上传。网页登录凭据权限可能超出聊天范围，请使用专用账号并确认接收后台属于自己。
8. 令牌失效时重新登录并再次点击授权即可更新，不用重新配对。若需恢复浏览器桥接，先在后台切回该方式，再在插件点击“使用已保存配置连接”。

## 当前范围与状态

- 自动读取普通与归档群的基本资料并核对成员身份，不返回私聊和最后一条消息正文。只采集勾选群的消息，最多选择 20 个，也可全部取消。
- 取消同步保留已有聊天记录，停止后续采集和发送，并取消尚未执行的任务；已开始执行的动作不能撤回。重新勾选时先导入最近消息快照，停用期间的旧消息不会追溯触发业务。
- 每 3 秒轮询消息，每批 20 条；首次导入最近最多 20 条历史快照，不触发旧消息的验证、转发或处罚。
- 文字收发、引用回复、发送确认，单条最多 2000 字。不确定的发送结果需要人工核对，不自动重发。
- 图片可在后台预览、点击查看原图，兼容之前导入的“[图片]”记录。图片通过需要管理员登录的后台接口读取；签名地址仅短暂用于读取，不持久保存。最多 8 MiB，支持 JPEG、PNG、GIF、WebP、AVIF。
- 图片发送支持单张 JPG / PNG（不超过 8 MiB），可附最多 2000 字说明。上传后须取得真实消息 ID 才显示成功；签名上传不携带币安登录 Cookie。后台“群发与通知”可上传、预览并选择目标群。
- 尚不支持币安删消息、踢人、禁言、入群审批及其他附件发送。
- 默认浏览器桥接不会上传登录 Cookie；一键直连只在用户主动授权后传送指定登录字段，不上传完整 Cookie。

## 运行与排查

- 只安装扩展不能独立运行机器人，还需要启动对应版本的 Superbot 后台。
- 浏览器桥接模式需要保持 Chrome 与聊天页运行。服务器直连验证通过后可以关闭；网页登录令牌失效仍需重新登录并再次点击授权，不支持独立续签。
- 扩展提示找不到聊天页：确认页面在安装扩展的这个 Chrome 配置中，地址为 `www.binance.com/.../square/chat` 或 `.../chatroom`；更新后刷新一次。广场页、群邀请落地页不属于聊天页。
- 点击保存后显示“配置已保存”只表示本机保存成功，是否已连接请看下方连接状态。JSON 错误、后台不可达、配对失效会分别提示。已有配置时可点击“使用已保存配置连接”，无需重复粘贴密钥。
- 后台暂时不可达：检查配对 JSON 的 `server_url`、后台是否运行、防火墙、域名证书及反向代理的 WebSocket 转发。
- 已找到聊天页但币安请求失败：v0.1.2 会显示失败发生在聊天身份、群资料、成员权限或消息列表，以及 `HTTP`、`API`、`NETWORK`、`TIMEOUT` 等类别。`100001005` 通常需要恢复该 Chrome 的币安登录；403 或非 JSON 响应需查看币安页面本身的提示。后台“连接 / 刷新”可重新核对，不要反复重建配对密钥。
- v0.1.3 按官方客户端使用每批 20 条消息，并区分消息数据为空、`messages` 字段缺失/为空/类型不匹配等情况。只反馈固定诊断文字，不上传完整响应；异常列表不会被当成“空群”推进消息游标。
- v0.1.4 根据当前成员角色、发送限制列表、群禁言和账号文字限制判断回复权限，兼容成员状态返回 `null`。发送前重新核对，未确认权限继续禁用。
- v0.1.5 修正账号文字限制的空值兼容：限制接口成功返回后，空数据或缺省/空值标志与官方客户端一致，表示未开启该限制。明确限制仍拒绝发送，接口失败和类型异常仍保持未知。升级时覆盖原扩展目录，在 `chrome://extensions` 重新加载，然后刷新币安聊天页并使用原配置连接。
- 后台提供管理员发送自检接口：只建立聊天连接并确认心跳，不发送群消息；只返回令牌结构类型和到期时间，不返回令牌、Cookie 或完整个人资料。到期信息只是读取令牌声明，不代表签名验证或自动续期能力。
- 后台提示账号变化：当前 Chrome 登录的币安账号与这个后台连接不一致，请切回原账号或新建连接。
- 后台账号被暂停：先在后台点击“连接 / 刷新”恢复，再打开扩展重新连接。
- 需要移除桥接时，可点击扩展的“断开并清除配置”，并在后台暂停该账号。

基础权限为 Chrome 存储、标签页和 `https://www.binance.com/*` 站点访问；页面桥接仅在币安聊天路径运行。源码随包提供，可在安装前审阅。ZIP 内的 `INTEGRATION.md` 提供协议和实现说明，`LICENSE` 为项目许可证。

浏览器桥接的 CSRF 令牌仅在浏览器内构造；可选的一键直连授权会将 cr00 交给配对后台，由服务器构造 CSRF 请求头。诊断只上报预定义错误类别、接口阶段、HTTP 状态和数字错误码，不上报 Cookie、CSRF 令牌、原始响应正文或异常原文。配对认证继续使用 HMAC-SHA256。
