# 系统架构

## 运行模式

完整服务由 React/Vite 管理台、NestJS API 与同进程 worker 组成。存储使用 PostgreSQL，开发环境可使用 PGlite；持久任务通过数据库 outbox 执行。生产部署支持 systemd/Caddy 与独立平台桥接进程。

公开演示是另一个构建入口：Vite 的 `demo` 模式将 API、媒体、实时通道与 QQ/币安登录组件替换为浏览器内模型。仅产出静态文件，使用 localStorage，无后台进程。详细边界见 [Pages 部署](cloudflare-pages.md)。

## 核心模块

- `auth.ts`、`security.ts`：管理员会话、CSRF、项目权限、凭据加密与签名校验。
- `accounts.ts`、`scope.ts`：连接账号、平台群发现、同步范围与能力快照。
- `messages.ts`、`governance.ts`：入站事件、审核与处理状态，按消息和策略版本检查任务有效性。
- `features.ts`、`jobs.ts`：群发、定时、抽奖、API Key、黑名单、持久投递、重试与人工核对。
- `chat.ts`、`presentation.ts`：消息快照、SSE、历史翻页、管理员鉴权的图片和头像读取。
- `adapters.ts`、`binance*.ts`、`qq*.ts`、`member-management.ts`：平台接入、登录、成员管理与验证。
- `packages/contracts`：事件、签名、握手、能力、权限、指令、回执与幂等约定。

## 数据与权限

平台支持与账号权限分别声明。有效操作取二者、群配置、同步范围与工作空间权限的交集；未知或过期的权限不能自动获得授权。群主、管理成员与机器人自身受保护。网页禁用不可用动作，服务端执行前再次核对。

消息判定、平台处理、发送结果分开记录。规则命中不等于实际删除/禁言成功。平台响应不明时使用 `unknown`，待人工确认；明确允许重试的失败才创建新的尝试，避免重复发送。

## 消息流

```text
平台事件 → 认证/验签 → 账号与群范围校验 → 持久消息
                                      ↓
                               审核与验证策略
                                      ↓
                              持久任务 / outbox
                                      ↓
                          执行前重新核对权限和版本
                                      ↓
                             平台回执 / 人工核对
                                      ↓
                           管理台 SSE、审计与任务状态
```

跨群同步只对审核允许的文本执行单向单跳转发，机器人发出消息不再次转发。图片群发独立创建逐群任务。历史导入不重放治理动作。

## 平台与部署隔离

TG 使用 Bot API；QQ 普通群使用非官方 OneBot 桥接；币安支持实验性 Chrome 桥接或服务器登录直连；自定义项目按签名协议接入。平台登录、接口变更与权限差异属于真实部署必须核对的条件。

生产凭据、数据、平台登录状态与备份都在 Git 之外。数据库备份需与加密密钥一起安全保存；公开演示不配置生产域名或 API 代理。
